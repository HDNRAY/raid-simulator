### 0b. ⚠️ "伤害 −5"到底怎么算（用户要求调整，待他确认）

现状：引擎里只有一条**门槛**语义，就是「卸」用的 `damageThreshold`：

```
伤害 ≤ N  →  整击作废（**连效果一起免**）
伤害 > N  →  伤害 − N
```

把"所有伤害 −5"直接挂成 Boss 的 `damageThreshold = 5` 会**继承这两半**，于是：

- 「击」（**5 点**）被**整击作废** → 一点伤害都没有（用户点名的就是这一条）
- 更糟的是"连效果一起免"：任何**小伤害段带着打断 / 眩晕**时，那些效果会被顺带免掉

⇒ **建议的调整**（待确认）：

1. **给"纯平减"一个独立字段**（例如受击方的 `flags.flatDamageReduce`），
   `computeDamage` 里只做 `伤害 − 5`，**绝不动** `damageThreshold` 的两半语义（「卸」照旧）
2. **保底 1 点**：这一击**本来有伤害**时，削完至少留 1 点
   （`final = max(0, floor(...) − 5)`，若 `final === 0 && 平减前 > 0` → `final = 1`）
   - 理由：与硬线"**玩家必须能赢**"同一条 —— 永不出现"完全打不动"；而且「击」这种
     小吃仍然**有**意义（5 → 1，多段小吃反而成了一种战术）
3. 备选（不推荐）：仍用 `damageThreshold`，只给它加一个"不整击作废"的模式位 ——
   一个 flag 两种语义，比新字段更容易被下一个人用错

⚠️ 主轴（用户 2026-10-16）：**加"防御的难度"，不加伤害** ——
"狂暴就已经是加伤了…我们游戏挨几次打就死了，加太多伤没意义"。
5 条里 ①是唯一加伤的（它本来就在），②压输出、④压打断分配、⑤压防御预算、③换题 ✓ 都合主轴。

## 2. 实现方案

### 2.1 ⚠️ ⑤ 回炁 ×0.8：**不能直接乘 0.8**

读代码得出的两个坑（都属于"用了不报错、结果错"）：

| 做法 | 结果 |
|---|---|
| 把每步回复 `1` 改成 `0.8` | `changeResource` 是 `Math.round(before + delta)`（资源是**整数**）⇒ 每步照样 `+1` ⇒ **一点都不慢** ✗ |
| 走 `energyRegen` 那个 stat | 它按 `Math.floor(每秒 / 10)` 落到每步 ⇒ `8/秒 → floor(0.8) = 0` ⇒ **完全不回** ✗（比设计狠 5 倍） |

⇒ 正确做法：**用"整数节奏"表达比例**（与"时间只有两个刻度"一致、**无状态**、不动确定性与回放格式）：

```
每 5 个逻辑步只回 4 点（第 5 步跳过）   ⇒  8/秒 ✓ 精确
判据：第几个逻辑步 % 5 === 0 → 这一步跳过
```

落点二选一（倾向前者）：

- **A. 新 stat `energyRegenScale`（0..1）**：`regenerate()` 读它，按"每 `round(1/(1-scale))` 步跳 1 步"实现；由挂在**玩家**身上的"难度光环"提供 `0.8`。以后要 0.9 / 0.75 只是换个值 ✓
- **B. 在 `regenerate()` 里按难度写死 0.8 的节奏**：省事，但把"难度"写进了引擎

⚠️ 验收必须钉"**真的变慢了**"：单测断言"10 秒里回的炁 = 80"（对照旧值 100），
**不是**断言"光环挂上了" —— 后者正是静默无效的样子。

### 2.2 难度怎么注入（这次唯一的结构性改动）

1. **纯函数**（可单测）：`difficultyFor(tier) → DifficultyModifiers`
   ```ts
   { enrage: false | { atMs, dmgMult }, damageThreshold?: number,
     energyRegenScale?: number, phase2: boolean }
   ```
2. **消费点两处**：
   - `app/battleSetup.ts`：按档给**玩家**挂"回炁光环"、给 **Boss** 挂"伤害门槛光环"（一段常驻 buff）
   - `data/units.ts` 的 `makeBoss` / `behaviorsFor`：按档**裁剪 Boss 的行为表**（第 1 档不挂 `enrage`；二阶段关掉就不挂 `onHpBelow`）
3. ⚠️ **先做管道、再上机制**：管道本身不改变现状（所有档 ≡ 今天的行为），
   这样每接一条都能单独对账、单独回退
