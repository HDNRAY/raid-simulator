# 「色欲」实现计划

> 日期：2026-10-10
> 前置：[设计文档](../specs/2026-10-10-lust-boss.md)
> 状态：**进行中**

---

## 分三步，每步都能单独验收

| 步 | 交付 | 验收 |
|---|---|---|
| **1** | 触发器引擎 | 挂 buff 上的 `onHitTaken` 触发器能在受伤后产出效果；有 CD 防抖；未支持的 hook 有**明确警告** |
| **2** | 眩晕效果 | 玩家被眩晕 3s 内**不能出招**（走现成的 `actionLock` → 拒绝原因 `locked`）；施放中被眩晕**打断**且**不退冷却** |
| **3** | 「色欲」内容 | 能作为备战界面的**第二个对手**选中并打完一局 |

---

## ⚠️ 能复用的一律复用（调研结论）

动手前先确认过现有机制，结论是**几乎每个需求都有现成落地点**：

| 需求 | 复用 | 说明 |
|---|---|---|
| 眩晕禁用行动 | **`BuffFlags.actionLock`** | 已在施法门禁**第一优先级**，拒绝原因就是 `locked`（"完全不能动"）。所以眩晕 = 一个带 `actionLock` 的 buff，**不必新造输入状态** |
| 打扰断当前施法 | `hitResolution` 里 `interrupt` 的现成写法 | 移除 `casts` 且**不动冷却** —— 正好符合设计 §4.1 的"不退冷却" |
| 反伤产出伤害 | `applyHitEffects` | 已支持 `damage` 效果走"非伤害分支"的通用路径 |
| 触发器产出 buff/资源 | `grant` / `resource` ability | 语义已知 |
| 印记的挂上 / 到期 | `applyBuff` + 现成事件 `buffApplied` / `buffExpired` | 日志与 UI 都能直接用 |

**唯一真正的新代码是"谁来在正确的时机派发 hook，并执行产出的 ability"** —— 见下。

## 步 1：触发器引擎

### 新建 `src/core/combat/triggers.ts`

纯函数，零依赖，可在 Node 里测：

```
runTriggeredAbilities(ctx, ownerId, hook, payload) -> void
```

职责：
1. 取 owner 身上**所有带 `triggers` 的 buff**
2. 过滤 `trigger.on === hook`
3. 逐个判 `when`（复用现有条件求值）、`cooldownMs`、`chance`（走 `ctx` 的种子化 RNG）
4. 执行 `then: Ability[]`

### ⚠️ 派发点只在"结算已完成"处（设计 §3.2）

本期只接 **3 个 hook**：`onHitTaken`（反伤）、`onBuffApplied` / `onBuffExpired`（印记）。

**未派发的 hook 要报警**：在 `content/validate.ts` 里加一条检查——内容里若用了
本期不支持的 hook，给**明确的不支持警告**，而不是让它静默失效。

### 执行 `Ability[]`

需要一个小的执行器（`grant` / `resource` / `damage` / `interrupt`）。
⚠️ **不新写一套**：`hitResolution.applyHitEffects` 已经能执行 `Effect`，
`grant` / `resource` 各几行，`interrupt` 复用已有写法。

### CD 与防循环

- `cooldownMs` 记在**触发器自己**身上（`BuffInstance` 需要能存"上次触发 tick"）
- ⚠️ 反伤会**再次派发 `onHitTaken`**（设计 §3.3 决定：反伤算受击）——
  玩家侧没有同款触发器所以不会无限弹，但仍要有 `cooldownMs` 兜底

## 步 2：眩晕效果

### `EffectKind` 加 `'stun'`

- `src/core/types/effects.ts`：`'stun'` 入联合类型 + `Effect` 的字段（buff 或时长）
- `src/core/combat/hitResolution.ts`：`stun` 分支
  1. 给目标挂一个带 `actionLock` 的眩晕 buff
  2. **打断目标当前施法**（复用已有写法，**不退冷却**）

⚠️ 眩晕 buff 的**持续时间就是禁用时长**，不要另存计时器（两处真相同步问题）。

### UI 反馈

复用现成的"技能被拒绝"通道显示"眩晕中" —— 输入层已在处理 `locked` 的显示。

## 步 3：「色欲」内容

新建 `src/data/entities/lustBoss.ts`：

| 内容 | 值（可玩起点，非校准） |
|---|---|
| 「轻吟」 | 0.9s 前摇 / 12 伤害 / CD 4s |
| 「缠绕」 | 2.0s 前摇 / 30 伤害 / CD 9s |
| 「魅惑」 | 1.4s 前摇 / 眩晕 3s + 打断 / CD 14s / **格挡无效** |
| 「欲望印记」 | 受伤挂 3s 印记（**已存在则不刷新**）→ 期间再受伤反伤 18 并**消耗**印记 |

- 注册进 `data/content.ts`
- 加进 `data/roster.ts` 的 `BOSS_ROSTER`
- ⚠️ `?prepare=skip` 目前写死默认对手，要支持 `?boss=lust` 才能用 e2e 测

### i18n

`色欲` 的技能名 / 描述 / 印记名。**描述里不写伤害类型**（已全删）。
