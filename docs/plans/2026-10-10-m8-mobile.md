## 0. 范围与验收

### 0.1 本计划要做的事

| # | 交付 | 验收 |
|---|---|---|
| **A** | 布局让位：日志面板与设置按钮上移，右下角空出给触屏 | 桌面上四块 UI 不重叠、不越界；右下角保留区在触屏模式下可用 |
| **B** | **唯一真相 + 监听**：一份控制布局同时驱动输入与画面 | 改一次绑定，**输入层与画面同时变**，不需要重建任何东西 |
| **C** | 触屏输入层：虚拟按键，支持"点一下"与"按住" | 触屏能放出所有技能，含按住型「防」 |
| **D** | 移动端显示与配置按钮的方案 | 按钮出现在预留区；有一个可用的配置界面 |
| **E** | 移动端不显示快捷键提示 | 技能按钮、功能按钮、（结算的）"Enter 再来一次"都不出现键名 |

### 0.2 已确认的前提（用户答复）

1. **形态**：同一套 canvas UI，触屏只是**再加一层虚拟按键**。
   不另做一套移动端布局 —— "唯一真相"要共享到底。
2. **手势**：支持**点一下**与**按住**两种。
   按住映射到引擎已有的 `hold` / `releaseSkill`，与键盘**完全同构**，
   所以技能语义（「防」= 按住减伤）一行都不用改。
3. **持久化**：本次**不做**。改完当前会话有效，刷新回默认 ——
   与现有键盘绑定保持一致（它现在也不持久化）。用户另排任务。

### 0.3 本计划**不包含**

- 按键配置的持久化（用户已明确另排）
- 真机手感调优（按钮大小/位置的手感需要真机验证）
- 横竖屏适配（本作锁定横屏，见 §5 风险）
- 虚拟摇杆 / 手势滑动（本作"无位移"，不需要方向输入）

## 1. 架构：唯一真相怎么落地

### 1.1 现状里已经能用的东西

| 已有 | 为什么关键 |
|---|---|
| 引擎只吃 `Action[]`（`useSkill`/`hold`/`releaseSkill`/`restart`…） | **触屏只要产出同样的 Action**，引擎与技能语义零改动 |
| `InputSource` 接口（`drain()`/`isHeld()`/`setBindings()`/`capture()`） | 触屏输入源可以直接实现它，或与键盘**合并**成一个 |
| `slotsFromBindings(bindings)` | 画面技能格已经从键位表推导 —— **移动端按钮沿用同一条路** |
| `FrameRegistry` + `FramePart` | 触屏按钮层可以作为一个帧部件注册进去，不必改场景 |

### 1.2 三个候选方案

#### 方案 A：`TouchLayout` 独立小模块 + 订阅（**推荐**）

新增 `src/input/touchLayout.ts`：

```ts
export interface TouchButton { readonly index: number; readonly skillId: string }
export interface TouchLayout {
  readonly buttons: readonly TouchButton[];
  /** 订阅变更 —— 这就是"监听变化"的落点 */
  subscribe(listener: (next: readonly TouchButton[]) => void): () => void;
  /** 当前值（只读） */
  current(): readonly TouchButton[];
  /** 替换（唯一的写入路径） */
  set(next: readonly TouchButton[]): void;
}
```

- 输入层（`TouchInputSource`）与画面层（`TouchButtonLayer`）**各自订阅**
- 写入只有 `set()` 一个入口 → 不可能出现"画面变了输入没变"
- 键盘那边**这一轮不动**（避免同时改两套）

**代价**：键盘与触屏暂时是两套表（但都遵守"单一入口 + 订阅"的形状，
将来合并很容易）。

#### 方案 B：统一的 `ControlStore`（键盘 + 触屏一起）

一份 `ControlLayout { keyboard, touch }`，一个 store，输入与画面都订阅它。
**优点**：真正的单一真相，键盘也算进去。
**代价**：要动 `main.ts` / `BattleLoop` 现有的 `bindings` 流转，
以及 `DEFAULT_BINDINGS` 的初始化路径 —— 这一轮的改动面会大很多，
而且是在"还没做完移动端"的时候先重构键盘。

#### 方案 C：不订阅，改完手动刷新

最省事，但**正是用户要摆脱的东西**（"监听变化"）。
会出现"画面变了、输入还是旧的"这类 bug —— 与之前
"改键后画面不跟着变"是同一类问题。**不推荐**。

### 1.3 推荐：先 A，后 B

A 能把移动端跑通且形状正确；等按键持久化那个任务做的时候，
再把 A 与键盘合并成 B（那时两边都要动，合并是顺路的）。

## 2. 布局让位（任务 A）

### 2.1 现状

| 部件 | 现在 | 问题 |
|---|---|---|
| 日志面板 | `x 792..952, y 216..388` | 占据右侧中段 |
| 设置按钮 | `y ≈ 424..474`，右下角 | 正压在预留区 |
| 技能栏 | `y 492..532, x 608..952` | 右下角 |

### 2.2 目标

把 **右下角 `x > 430 && y > 430`** 这块空出来（移动端按钮用）：

```
y=150   ┌─────────────┐
        │  日志面板    │  x 792..952（上移，底 322）
        │             │
y=322   └─────────────┘
        ...
y=380       [⚙ 设置]     上移到这里
        ...
y=430  ──────────────────  ← 预留区上边界
        │  触屏按钮从这里往上/往左长  │
y=492   [技能栏 Q W E R A S]
y=532
```

- **日志面板**：`y 216 → 150`（底边 322，距预留区 108px）
- **设置按钮**：`y ≈ 424..474 → ≈ 380..430`（贴着预留区上沿）
- 两者都在 `LAYOUT` 表里改，不散落魔法数

### 2.3 ⚠️ 只在触屏模式下让位？

这里有一个**必须现在就定的取舍**：

| 选项 | 说明 |
|---|---|
| **A1：永久让位**（两种模式都上移） | 布局只有一套，最简单；桌面下方会空一块 |
| **A2：按模式动态让位** | 桌面保持现状（更紧凑），触屏才上移。但 `LAYOUT` 是静态常量，要变成"按能力解析" |

**建议 A1**：用户的原话是"logpanel 尽可能地上移，设置按钮也上移" ——
听起来就是要**永久上移**，而且一套布局最省事。触屏按钮只在触屏出现，
桌面那块空着也无妨（本来就是"战斗画面"的一部分）。

## 3. 触屏输入层（任务 C）

### 3.1 为什么可以极薄

引擎的 `Action` 已经能表达一切：

| 触屏动作 | 产出的 Action |
|---|---|
| 按下按钮 | `{ type: 'useSkill', skillId }` |
| 按住不放 | 同上 + `{ type: 'hold', skillId }`（引擎按逻辑步扣费） |
| 松开 | `{ type: 'releaseSkill', skillId }` |

**技能不需要区分"点按型"还是"按住型"** —— 引擎的 `hold` 对非按住型
技能会自动退化成普通施放（`startHold` 里有这条兜底）。所以按钮层
可以**无脑**同时发 `useSkill` + `hold`，由引擎决定语义。

### 3.2 多指与手势

- 用 **Pointer Events**（`pointerdown/move/up/cancel`）+ `pointerId` 跟踪
  每个手指，支持"同时按住两个按钮"
- canvas 加 `touch-action: none`，否则浏览器会把手势当成滚动/缩放
- ⚠️ **一个 `pointerId` 只能占一个按钮**；移到别的按钮不算"按住那个"
  （否则「防」会被误触发）

### 3.3 与现有鼠标处理的冲突

`main.ts` 现在用 `pointerdown` 做：设置按钮命中、设置面板命中、
（可能还有）关掉结算。触屏按钮层要**插在最前面**：
命中按钮就 `preventDefault` 并消费，否则落回原逻辑。

## 4. 按钮显示与配置的方案（任务 D）

这是用户明确要的那份"方案"，我给**三个层次**的选项。

### 4.1 显示：按钮从哪来

**D1：两套绑定表，一个"编辑目标"选择器**（推荐）

⚠️ 核实后修正：设置页现在读的是 **`bindings`（键位表）**，
不是 `PLAYER_SKILLS` —— 所以"哪些技能出现在设置里"这件事，
**已经**由绑定表决定了（「闪」就是靠 `DEFAULT_BINDINGS` 里那条空 key
才出现在设置里的）。

这带来一个好消息：**设置页天然就是"编辑某一张表"的结构**。
所以最小改动是：

- 键盘绑定表 → 桌面技能格（现状，不动）
- 触屏绑定表 → 触屏按钮（新增）
- 设置页加一个**"编辑目标"**选择：`[键盘] [触屏]`
  - 选"键盘"→ 现在的一切（点技能格 = 改键）
  - 选"触屏"→ 点技能格 = 把它绑到触屏按钮位

也就是说 §4.2 的 D-a 里的"目标按钮行"其实是**两种目标**：
编辑哪张表（键盘/触屏），以及（触屏下）编辑哪一个按钮位。

**D2：触屏直接复用键盘绑定**
省一张表，但改键会影响触屏、改触屏会影响键——两边互相干扰。

**D3：触屏按钮不由技能驱动，而是玩家自由排布（拖拽）**
自由度最高，但需要拖拽、吸附、碰撞检测——**远超本次范围**。

### 4.2 配置界面：怎么绑定

我把候选收窄到两个（都在**现有设置面板内**，不新开界面）：

**D-a：在按键页上方加一行"目标"**（推荐）

```
┌─ 按键 ─────────────────────────────┐
│ 编辑: [键盘] [触屏]                │  ← 编辑哪张表
│ 触屏位: [①攻] [②轰] [③凝] …        │  ← （触屏时）选中配哪个按钮位
│                                    │
│  [攻]    [轰]    [凝]              │  ← 技能格：点一下 = 绑到当前目标
│  [破]    [避]    [防]              │
│  [闪]                              │
└────────────────────────────────────┘
```

- 选"键盘"时第二行隐藏，行为与现在**完全一致**（零回归风险）
- 选"触屏"时第二行出现，技能格变成"绑到选中的触屏位"
- 空出的按钮位可以"清空"（再点一次选中的按钮位）

- **复用已有的技能格**（`KeyGrid`）与已有的"点一下 = 选中"交互
- 新增的只有顶部那一行"目标按钮"
- 逻辑：先选目标 → 再点技能 → 该技能绑到那个按钮（原占用者自动让位）
- 要"清空某个按钮"就再点一次它（或点"清空"）

**D-b：点技能格 → 弹出"绑到哪个按钮"**
多一次交互层级，面板里放不下浮层（canvas 手绘），要另做一套弹层。

**建议 D-a**：新增一个组件（"目标按钮行"）+ 改一处点击路由，
就能同时满足"配置按钮"与"复用技能格"。

### 4.3 移动端如何进入设置

触屏没有键盘，所以：

- **设置按钮必须够大且可点**（现成，`SettingsButton` 已支持点击）
- 设置面板内的**所有交互都要能点**：
  - tab、技能格、恢复默认、关闭 —— 现在**都已有鼠标命中测试**
  - ⚠️ **新增的"目标按钮行"必须从一开始就支持点击**（别只做键盘）
- ⚠️ 面板尺寸 640×520 在小屏上可能过大 —— 配合"UI 缩放"
  （用户可调，`UI_SCALE_MIN=0.5`）即可，本次不另做移动端专用尺寸

## 5. 隐藏快捷键提示（任务 E）

### 5.1 需要一个"平台能力"的唯一来源

新增 `src/render/platform.ts`：

```ts
export interface PlatformCaps {
  /** 有粗指针（手指）—— 用 matchMedia 探测，不看 UA */
  readonly touch: boolean;
  /** 是否显示键盘快捷键提示 */
  readonly showKeyHints: boolean;
}
```

⚠️ **探测用能力而不是 UA**：`matchMedia('(pointer: coarse)')`。
混合设备（触屏笔记本）会同时为真 —— 所以**两种输入源都保留**，
只是隐藏键名提示。

### 5.2 要隐藏的键名（穷举）

| 位置 | 现状 | 改动 |
|---|---|---|
| 技能格 | `攻 Q` / `轰 W` | 触屏时**只显示技能字**（`KEY_HIDDEN` 时不画 key 标签） |
| 设置按钮 | 齿轮左上角 `Esc` | 触屏时不画 |
| 设置面板 | tab `通用 (G)` / `恢复默认 (R)` / 技能格 `Q/W/E…` | 触屏时不画 |
| 结算 | `screen.hintRestart: '按 Enter 再来一次'` | 触屏时换成"点击屏幕再来一次" |
| 改键提示 | `keysHint: '方向键选择，Enter 改键，Esc 返回'` | 触屏时换成"点技能改绑" |

⚠️ 最后两条是**文案差异**，必须走 i18n（`hintRestartTap` 等新 key），
不许在渲染层拼中文字符串（i18n 规范 I1，lint 会拦）。

### 5.3 点击屏幕重开 —— ⚠️ 但"重开"目前是坏的

**实测发现（这条改变了任务性质）**：

```
失败后状态: defeat
注入 restart action → 状态仍是 defeat，tick 卡在 663 不动
```

`restart` 这个 action **从来没有被任何地方产出**：
- `core/actions.ts` / `render/viewModel.ts` 里都有类型定义
- `battleLoop.step()` 会消费它（`tail.some(a => a.type === 'restart')`）
- `battleLoop.requestRestart()` 也存在
- 但**没有任何调用者** —— 输入层不产、`main.ts` 的 keydown 里也没有

所以 `screen.hintRestart: '按 Enter 再来一次'` 这行字**在骗玩家**：
按 Enter 不会重开。`RenderAction` 联合里的 `restart` 也是死类型。

**这不是移动端的问题，是现在就存在的 bug。** 它让 M8-8 从
"改个文案 + 加个点击"变成"**先把重开接通**，然后键盘与触屏共用它"。

修法（两种，见 §9 待拍板）：
- **E1**：`main.ts` 在结算态把 `Enter` 翻译成 `{ type:'restart', seed, atTick }`
  推进输入源 —— 复用现有通路，改动最小
- **E2**：`main.ts` 直接调 `loop.requestRestart()` —— 更直接，
  但绕过了"动作"这条统一通路（将来录制/回放不含重开）

触屏则统一为：**点结算面板任意处 = 重开**。

- ⚠️ 与"点面板外关闭设置"的 `outside` 分支**判据不同**，别串味

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **真机手感**（按钮大小/间距） | 桌面看起来对、真机上按不准 | 按钮尺寸给到 ≥ 44 逻辑像素（业界触屏最小可点区）；真机再调 |
| **横竖屏** | 竖屏时 960×540 会很小 | 本作锁定横屏：`screen.orientation.lock('landscape')` 或提示用户旋转。**本次只提示，不强制** |
| **混合设备**（触屏笔记本） | 同时有鼠标与手指 | 两种输入源都保留；只隐藏键名 |
| **`pointerId` 串台** | 一指滑到另一按钮被当成按住 | 每个 pointerId 绑定到**按下时**的按钮，移动不切换 |
| **让位后桌面变空** | 桌面观感变松散 | 可接受（§2.3 A1）；若不可接受再做成按模式解析 |
| **文件行数**（AGENTS.md §3） | 新增文件把邻近文件推过 700 行 | 新增的都独立成文件；`main.ts` 已经 690+ 行，**路由逻辑要抽出去**而不是继续堆 |
