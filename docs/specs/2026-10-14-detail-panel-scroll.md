### 用户拍板的三件事

- **全部一起滚**（名字、头像、生命上限、所有能力）—— 不是"名字固定、其余滚"
- 合并后**完全不区分**被动（不加标签、不换色）
- 顺序：**招式在前、被动在后**

## 2. ⚠️ 考古：为什么当年写的是"**整行才算数**"

这两条策略（`prepareDetailViewport.ts` / `prepareDetailPanel.ts`）**不是随手写的**，
根因是一句技术限制（原注释）：

> ⚠️ **为什么是"整行"而不是"相交就画"**：**Pixi 的一段 `Text` 不能裁一半**
> —— "相交就画"必然让跨在面板下缘的那一行有半截露在外面，而露出多少
> 取决于那一行折了几行（Boss 的说明 2~3 行 ⇒ 最多露 ~50px）。

于是有了两条**互相配合**的策略：

| 策略 | 代码 | 作用 |
|---|---|---|
| 必须**整行**落在视口里才画 | `DetailViewport.shows()`：`nameTop >= viewTop && endTop <= viewTop + viewH` | 不让半行露到面板外 |
| 落笔时**吸附到行顶** | `DetailViewport.drawnViewTop()` → `snapToRowTop()` | 让上面那条不产生"奇怪的空白" |

⚠️ **它们一起工作得很好 —— 前提是"一行 = 单行文本"**（`LogReviewPanel` 的
一条日志、`SkillDetail` 的固定 `LINE_H`）。而详情面板的一行是
**变高的多行块**（一条技能 = 名字 + 2~3 行说明），于是：

```
"整行放得下才画"  ⇒ 一条放不下的高行**整条不画** ⇒ 【下面大片空白】✗
"吸附到行顶"      ⇒ 滚一点点就整块跳到下一行   ⇒ 【滚下去突然出现】✗
```

= 用户报的那两条症状，**是同一个取舍的两个副作用**。

## 3. 仓库里**早就有正确做法**

`ui/settings/SkillDetail.ts` 面对的是同一个问题（长说明 + 滚动），它的做法是：

| | 详情面板（旧） | `SkillDetail`（对） |
|---|---|---|
| 折行 | 交给 Pixi `Text` 的 `wrap` ⇒ **一整块** | `ui/settings/wrapText.ts` **折成"一行一个 label"** |
| 裁剪 | 做不到 ⇒ 只能"整行才算数" | `clipToWindow()` **逐行**判可见性 |

⇒ 所以这不是"新发明一套"，而是**把详情面板对齐到既有先例**。
⚠️ 同样绕开了"Pixi `mask` 在 headless 里不生效"（AGENTS.md §3e）。

## 4. 设计

### 4.1 数据（已落地，`5d673d5`）

- `bossPassives` 复用 `skillRow()` ⇒ 被动行**有名字也有说明**
  （`PassiveSkillDef` 有 `descKey`；五条被动的文案当时就写好了，只是没取）
- Boss rows = **`[...skills, ...passives]`**，两个小节标题行删掉

### 4.2 绘制：行 → **逐行 label**（#1 的关键）

- 折行改用 `wrapText()`：一条能力的说明变成 **N 个单行 label**
- 视口可见性判据从"整行落在里面"改成 **"这一行（单行）与视口相交"**
- ⇒ **`shows()` 的"整行"与 `snapToRowTop()` 的吸附都可以删掉**，滚动变成连续的
  （CSS `overflow:scroll` 的手感）
- label 池从"`{name, body}` 一条两个"改成**按行**复用（名字一行 + 说明 N 行）

### 4.3 头部并入滚动内容（#2）

- 头部（头像框 + 名字 + 副标题）从"钉住的带"降级为**内容的第一块**
- `prepareDetailMetrics.bodyTopOf()` 那条"固定带"随之删掉；三类
  （`player` / `qiji` / `boss`）统一走同一条路
- ⚠️ `PREPARE_LAYOUT.detailPad` 仍然决定滚动区的边界（它不该跟着滚）

### 4.4 文件（AGENTS.md §3）

`ui/prepareDetailPanel.ts` 现在 **660 行**，这次改动会让它越过 700 ⇒
**把头部抽成 `ui/prepareDetailHeader.ts`（造 / 量 / 画）**，panel 只剩
"把行列表交给 viewport + 画滚动条"。用户已同意这次拆分。
