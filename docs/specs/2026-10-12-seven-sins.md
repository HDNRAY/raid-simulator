## 8. 嫉妒（Envy）

> **以固定间隔，平衡与玩家的血量差**，当然如果它的血量比例比你高就不会有啥动作，
> 如果比你低，**根据百分比差距的 1/3 的百分比**，**扣除玩家的血量**，
> **增加它的**，都是**自身百分比**。

### 把它写成算式（这样才好讨论）

设：
- `H_b` = Boss 当前血量 **占自己上限的百分比**
- `H_p` = 玩家当前血量 **占自己上限的百分比**

**固定间隔**（每 N 秒）结算一次：

```
若 H_b >= H_p → 什么都不做
若 H_b <  H_p → 差值 d = H_p - H_b
                取走 d / 3 这个百分点
                  · 玩家失去：自己上限的 (d/3)%    ← "都是自身百分比"
                  · Boss 回复：自己上限的 (d/3)%
```

⚠️ **"1/3 的百分比"我按"差值的 1/3，单位是百分点"理解** ✓ ——
如果理解错了请纠正（这条决定了它是"慢慢追平"还是"一下就追平"）。

### 为什么这个设计有意思

它**自动随玩家的表现调难度** ✓ —— 玩家打得越快，它偷得越多 ✓
而且"血量比例比你高就不动"是个**很好的刹车** ✓（不会把玩家直接吸死 ✓）

### 缺什么

| 缺 | 说明 |
|---|---|
| ❌ **固定间隔的定时能力** | 引擎的 `Behavior` 只有 `opener` / `onHpBelow` / `enrage` / `rotation` / `weightedRotation` ✗ 没有"每 N 秒" ✗（轮转的 `gapMs` 是"两次出招之间"，不是独立定时器）|
| ❌ **"按百分比转账血量"这个效果** | 现有的 `resource` 效果改的是**绝对值**（`delta`）✗ 没有"按目标上限的百分比" ✗ |
| ⚠️ **比较用的"另一端"血量** | 效果的数值是**静态表达式** ✓ 而这里要读**双方的比值** ✗ —— `Expr` 里有 `hpRatio` 之类的吗？要查 |

## 9. 暴怒（Wrath）

> **根据受伤次数**，**较少技能 cd**，**增加伤害**。

⚠️ "较少"应是"**减少**"（错别字）✓

### 缺什么

**"受伤次数"是一个计数器** ✗ —— 而引擎的计数器（`Combatant.counters` /
`Expr.counter`）**是未实现的**（读出来恒 0 ✗，肉鸽文档列为 **W1**）。

⚠️ **所以暴怒与肉鸽的"炁机解锁条件"（"成功使用 3 次截"）依赖的是同一套东西** ✓
—— 做 W1 的时候一次做掉两件事 ✓

另外"**减少技能 CD**"：引擎有 `cooldown` 效果（`EffectKind:'cooldown'` ✓
"负数为退还" ✓）—— **这条是现成的** ✓

## 10. 懒惰（Sloth）

> **高血量，高回复**，**30% 血进二阶段**，**不再高回复**，**但是变强？**

### 已有

- ✅ 血量高 → `BOSS_HP_DISPLAY` 那套（但要**每 Boss 不同**，见下）
- ✅ 高回复 → `heal` / `resource` 效果 ✓
- ✅ 30% 进二阶段 → `onHpBelow { ratio: 0.3 }` + `grantBuff` ✓
  （傲慢的「回补」就是 `ratio: 0.4` ✓ 同一个机制 ✓）
- ✅ "不再高回复" → 二阶段 buff 里**移除/覆盖**回血能力 ✓

### ⚠️ 缺什么

| 缺 | 说明 |
|---|---|
| ⚠️ **"变强"要定义** | 用户自己标了"？" —— **这是开放问题**（见 §5）|
| ⚠️ **每 Boss 不同血量** | 现在 `BOSS_HP_DISPLAY = 420` 是**全局一个** ✗ 而懒惰要"高血量" ✓ → 需要"每个 Boss 自己的上限" ✓（与三个角色的 150/120/100 是**同一个缺口** —— 肉鸽文档的 **W6**）|

### 它的设计形状（值得注意）

"**二阶段反而变弱回复**"是个**反直觉但有意思**的转折 ✓ ——
一阶段打不动（高血高恢复），二阶段它放弃回复、变成纯粹的进攻压力 ✓
**这是"时间压力"而不是"血条压力"** ✓ 与傲慢的「回补」正好相反 ✓

## 11. 贪婪（Greed）

> **无限叠加，指数级增强的 buff 技能**，**可以被打断**。

### 已有

- ✅ 可打断 → `interruptible: true` ✓
- ✅ 堆叠 → `maxStacks` / `stacking` ✓
- ✅ **指数级** → 修正树有 `mult`（相乘）✓ —— 叠 N 层就是 **N 次乘法** ✓
  （`damageMult` 的语义就是"相乘"，见 `core/types/stats.ts` 的说明 ✓）

### ⚠️ 缺什么

| 缺 | 说明 |
|---|---|
| ⚠️ **"无限"** | `maxStacks` 是必填还是可省？如果必须给一个数，那"无限"就用一个大数 ✗ 见 §5 |
| ⚠️ **指数级会炸** | 每层 ×1.2，10 层就是 ×6.2，20 层 ×38 ✗ —— **必须有"玩家能在它叠起来之前打断"的节奏**，否则这是个**必输局** ✓ 这是**平衡问题**，不是引擎问题 ✓ |

### 它的设计形状

**"可以被打断的、越叠越强的 buff"** = 一场**打断资源的竞赛** ✓
玩家要在"打输出"和"留打断"之间取舍 ✓ —— 和傲慢「回补」的取舍**同源** ✓

## 12. 暴食（Gluttony）

> **攻速高**，**每次命中**，会**随机吸取你 血 炁 缠 百分比最高一项的 25%**。

### ⚠️ 这句话有两种读法 —— 需要用户确认（见 §5）

| 读法 | 含义 |
|---|---|
| **(A)** 从血/炁/缠里**挑"你当前百分比最高"的那一项**，吸它 **25%** | "专打你最强的那一项" |
| **(B)** 从血/炁/缠里**随机挑一项**，吸它 **25%** | "不可预测的骚扰" |

⚠️ 原话里"**随机**吸取你 血 炁 缠 **百分比最高一项**的 25%"把两个词放在了一起 ✗
—— 而这两种读法的**玩法完全不同** ✓ (A) 是"惩罚你的强项"，
(B) 是"随机干扰" ✓

### 已有 / 缺什么

| 项 | 状态 |
|---|---|
| ✅ 攻速高 | 轮转 `gapMs` 调小即可 ✓（傲慢是 4000ms）|
| ❌ **"吸取资源"这个效果** | 没有 ✗ —— 现有的 `resource` 只能**扣自己的或目标的绝对值**，没有"**按当前百分比吸**" ✗ |
| ⚠️ **"每次命中"触发** | 需要触发器 ✓ (`onHitTaken` **是活的** ✓ —— 这个有了 ✓) |
