## 0.1 ⚠️ 实现之后的实际做法（2026-10-14，与上面那张表对账）

上面那张表是**设计期**的判断，落地时有两件事变了，都值得记下来 ——
因为**当时的判断是对的，解法是错的**（都绕开了"加一条新管线"）：

| 当时的要求 | 当时的结论 | **实际做法** |
|---|---|---|
| 嫉妒要"**固定间隔**的定时能力" | ❌ 引擎没有 ✗ | **不需要定时器**：把它做成一条**长 CD 的读条技**（28 秒）—— 顺序轮转天然只出一个动作，而"固定间隔"由 CD 给 ✓ |
| 暴怒要"按**受伤次数**减 CD" | ❌ 需要 W1 计数器 ✗ | ⚠️ **用户后来改口**："暴怒的那个技能以后靠 buff 实现" → 计数器**至今没有消费者**（W1 仍是"没有已知消费者"）✓ |
| 贪婪要"随机频率 3–5 秒" | （当时没提） | ✅ **公共机制**：`TriggerDef.cooldownRangeMs` + **`onTick` 钩子真的派发**（种子化 RNG，重放逐位可复现）✓ |
| 嫉妒 / 暴食要"按百分比转账 / 吸取资源" | ❌ 需要新效果 ✗ | ✅ **`EffectKind: 'transfer'`**（扣目标、按**实际** delta 补给施法者；**不走命中管线**）—— 嫉妒的「妒火」「夺息」在用 ✓ |
| 贪婪的"每层 +10% 伤害" | ⚠️ 以为 `mult` 就够了 | ⚠️ **不够**：`BuffDef.damageMultBoost` **声明了但没有任何引擎分支读**（**狂暴从来就没生效过**）→ 已接上 ✓ |

⚠️ **顺手修掉的三个"死字段"**（都是"声明了、写进内容不报错、实际静默无效"）：

| 字段 | 症状 | 落点 |
|---|---|---|
| `BuffDef.damageMultBoost` | **狂暴（`dmgMult`）从来没生效过** | `core/combat/stats.ts` 每层推一条 `mult` 修正 |
| `DefenseFlags.damageTakenMult` | 易伤 / 弱点 / 「见红」全无效 | `core/combat/damage.ts` 的 `computeDamage` |
| `Effect.when` | 效果上的条件被忽略（「夺息」的 60% 门槛） | `core/combat/hitResolution.ts` |

**另外删掉了两个重复的属性名**：`castSpeed` / `cooldownRate` —— 它们与
`haste` 是同一件事，而且**没有任何引擎分支读**。所以"减读条 / 减 CD"
的**唯一公共机制是 `haste`**（`hastedCastTime` / `hastedCooldown`），
贪婪的「敛财」就是它的第一个内容消费者。

## 8. 嫉妒（Envy）

> **以固定间隔，平衡与玩家的血量差**，当然如果它的血量比例比你高就不会有啥动作，
> 如果比你低，**根据百分比差距的 1/3 的百分比**，**扣除玩家的血量**，
> **增加它的**，都是**自身百分比**。

### 把它写成算式（这样才好讨论）

设：
- `H_b` = Boss 当前血量 **占自己上限的百分比**
- `H_p` = 玩家当前血量 **占自己上限的百分比**

**固定间隔**（每 N 秒）结算一次：

```
若 H_b >= H_p → 什么都不做
若 H_b <  H_p → 差值 d = H_p - H_b
                取走 d / 3 这个百分点
                  · 玩家失去：自己上限的 (d/3)%    ← "都是自身百分比"
                  · Boss 回复：自己上限的 (d/3)%
```

⚠️ **"1/3 的百分比"我按"差值的 1/3，单位是百分点"理解** ✓ ——
如果理解错了请纠正（这条决定了它是"慢慢追平"还是"一下就追平"）。

### 为什么这个设计有意思

它**自动随玩家的表现调难度** ✓ —— 玩家打得越快，它偷得越多 ✓
而且"血量比例比你高就不动"是个**很好的刹车** ✓（不会把玩家直接吸死 ✓）

### 缺什么（设计期的判断）

| 缺 | 说明 |
|---|---|
| ❌ **固定间隔的定时能力** | 引擎的 `Behavior` 只有 `opener` / `onHpBelow` / `enrage` / `rotation` / `weightedRotation` ✗ 没有"每 N 秒" ✗（轮转的 `gapMs` 是"两次出招之间"，不是独立定时器）|
| ❌ **"按百分比转账血量"这个效果** | 现有的 `resource` 效果改的是**绝对值**（`delta`）✗ 没有"按目标上限的百分比" ✗ |
| ⚠️ **比较用的"另一端"血量** | 效果的数值是**静态表达式** ✓ 而这里要读**双方的比值** ✗ —— `Expr` 里有 `hpRatio` 之类的吗？要查 |

---

### ✅ 已实现（2026-10-14）—— 实际的做法

代码：`src/data/jealousyBoss.ts`（`JEALOUSY_BOSS`）

| 招 | 起手 | CD | 可打断 | 效果 |
|---|---|---|---|---|
| **剜** | 0.6s | 3s | 可 | 35 伤害（填充） |
| **殁** | 1.8s | 8s | **可** | 70 伤害 + 挂「见红」（受到的伤害 **+30%**、4 秒） |
| **夺息** | 1.0s | 10s | ❌ **不可** | 你的**炁 > 60** 时，偷走**当前值的一半**（`transfer`、门槛用 `effect.when`） |
| **妒火** | 1.4s | **28s** | 可 | `(你血量% − 它血量%) / 3` **点**：**你扣多少、它就回多少** |

**三条与设计期不同的决定**（都绕开了"新管线"）：

1. **"固定间隔"不用定时器**：妒火是一条**长 CD 的读条技**，而且走
   `Behavior: onCooldown`（**CD 一到就出手、不抽签**，优先级在轮转之前）
   —— 所以它的节拍只由自己的 CD 决定，而"一个 tick 只有一个动作"是引擎
   既有的不变量 ✓
2. **"按百分比转账"落成 `EffectKind: 'transfer'`**：一条效果同时扣目标、
   按**实际** delta 补给施法者（所以"你掉多少它就回多少"是**结构性**的，
   不是两处各算一遍）。⚠️ 它**不走命中管线** —— 不吃护甲 / 减伤 / 暴击，
   也不能闪避；反制手段是**打断那条读条** ✓
   —— 「夺息」也复用它（换一个 pool），这就是"共用底层原语"的收益 ✓
3. **"比较双方血量"落成 `Expr: 'hpRatio'`**：表达式现算，不用静态值 ✓
   （当年那一行写的是"要查"—— 查的结果是**没有**，所以新加了它）

⚠️ **数值全是初稿**：28 秒的 CD、420 的血、每招的伤害都等实测定。
⚠️ **用户定过一条口径**："按差值的 1/3，但 **Boss 回的是数值、不是百分比**"
—— 例子：你 80% / 它 20% ⇒ `(80−20)/3 = 20` ⇒ **你扣 20 点、它回 20 点**。

## 9. 暴怒（Wrath）

> **根据受伤次数**，**较少技能 cd**，**增加伤害**。

⚠️ "较少"应是"**减少**"（错别字）✓

### 缺什么

**"受伤次数"是一个计数器** ✗ —— 而引擎的计数器（`Combatant.counters` /
`Expr.counter`）**是未实现的**（读出来恒 0 ✗，肉鸽文档列为 **W1**）。

⚠️ **所以暴怒与肉鸽的"炁机解锁条件"（"成功使用 3 次截"）依赖的是同一套东西** ✓
—— 做 W1 的时候一次做掉两件事 ✓

另外"**减少技能 CD**"：引擎有 `cooldown` 效果（`EffectKind:'cooldown'` ✓
"负数为退还" ✓）—— **这条是现成的** ✓

## 10. 懒惰（Sloth）

> **高血量，高回复**，**30% 血进二阶段**，**不再高回复**，**但是变强？**

### 已有

- ✅ 血量高 → **每个 Boss 自己的 `hp`**（2026-10-14 已做，见下）
- ✅ 高回复 → `heal` / `resource` 效果 ✓
- ✅ 30% 进二阶段 → `onHpBelow { ratio: 0.3 }` + `grantBuff` ✓
  （傲慢的「回补」就是 `ratio: 0.4` ✓ 同一个机制 ✓）
- ✅ "不再高回复" → 二阶段 buff 里**移除/覆盖**回血能力 ✓

### ⚠️ 缺什么

| 缺 | 说明 |
|---|---|
| ⚠️ **"变强"要定义** | 用户自己标了"？" —— **这是开放问题**（见 §5）|
| ✅ **每 Boss 不同血量** | **2026-10-14 已做**：`data/bossDefs.ts` 的 `BossDef.hp` + 各 Boss 文件里的 `*_HP`（原先 `BOSS_HP_DISPLAY = 420` 是全局一个 ✗）。⚠️ 懒惰要的"高血量"**现在有地方写了**，但**那个值还没定**（四个 Boss 暂时都是 420）|

### 它的设计形状（值得注意）

"**二阶段反而变弱回复**"是个**反直觉但有意思**的转折 ✓ ——
一阶段打不动（高血高恢复），二阶段它放弃回复、变成纯粹的进攻压力 ✓
**这是"时间压力"而不是"血条压力"** ✓ 与傲慢的「回补」正好相反 ✓

## 11. 贪婪（Greed）

> **无限叠加，指数级增强的 buff 技能**，**可以被打断**。

### 已有

- ✅ 可打断 → `interruptible: true` ✓
- ✅ 堆叠 → `maxStacks` / `stacking` ✓
- ✅ **指数级** → 修正树有 `mult`（相乘）✓ —— 叠 N 层就是 **N 次乘法** ✓
  （`damageMult` 的语义就是"相乘"，见 `core/types/stats.ts` 的说明 ✓）

### ⚠️ 缺什么（设计期）

| 缺 | 说明 |
|---|---|
| ⚠️ **"无限"** | `maxStacks` 是必填还是可省？如果必须给一个数，那"无限"就用一个大数 ✗ 见 §5 |
| ⚠️ **指数级会炸** | 每层 ×1.2，10 层就是 ×6.2，20 层 ×38 ✗ —— **必须有"玩家能在它叠起来之前打断"的节奏**，否则这是个**必输局** ✓ 这是**平衡问题**，不是引擎问题 ✓ |

### 它的设计形状

**"可以被打断的、越叠越强的 buff"** = 一场**打断资源的竞赛** ✓
玩家要在"打输出"和"留打断"之间取舍 ✓ —— 和傲慢「回补」的取舍**同源** ✓
⚠️ **2026-10-14 补正**：「傲慢」的「回补」后来改成**不可打断**了
（用户："傲慢的回血 不能打断"），所以贪婪的「敛财」现在是**唯一**一个
"可打断的、越拖越强"的机制 —— 那个取舍今天只在这里成立。

### ✅ 已实现（2026-10-14）—— 最终口径

代码：`src/data/greedBoss.ts`（`GREED_BOSS`）。
用户后来把"无限"收成 **9 层**，并且要求"**每层只变强一点点，但是全面**"：

| 招 | 起手 | CD | 效果 |
|---|---|---|---|
| **敛财** | 2.0s，**可打断** | 6s | 叠一层「敛财」：**每层伤害 +10% / 回血 +1/秒 / 读条 −10%**（最高 9 层） |
| **掠刃** | 0.8s | 3s | 30 伤害 |
| **重利** | 1.6s | 8s | 55 伤害 |
| **弱点**（被动） | — | **随机 3–5 秒** | 给**双方**各挂 2 秒 —— **受到的伤害翻倍** |

**三处与设计期不同的决定**：

1. **"全面"落在三个属性上**（伤害 / 回血 / 读条）—— 而"读条 −10%/层"
   用的就是**公共机制 `haste`**（`hastedCastTime` / `hastedCooldown`）
   ⚠️ `haste` 的钳制是 **[0, 0.5]**，所以第 6–9 层的"读条"部分会被钳掉
   （伤害与回血照涨）—— 这是有意的天花板，要放开就是改 `STAT_RULES`
2. **"随机频率"落成公共机制**：`TriggerDef.cooldownRangeMs` +
   **`onTick` 钩子真的派发**（在此之前它只在 `Hook` 里声明、引擎从不派发）
3. **"受伤翻倍"落成 `DefenseFlags.damageTakenMult`** —— ⚠️ 这个属性
   **声明了很久但没有任何引擎分支读**（第一次真实消费者就是「弱点」），
   已接进 `computeDamage` ✓

⚠️ **轮转顺序是"先叠层、再打人"**（敛财优先）—— 这**不是**"长 CD 在前"
那条惯例（重利 CD 比敛财长）。有意为之：这个 Boss 的题是"层数在涨"，
叠层必须压过输出，否则它退化成一个普通 Boss（见 `GREED_BEHAVIORS` 的注释）。

⚠️ **数值全是初稿**：9 层、每层 +10%、6 秒的叠层 CD、420 的血都等实测定
（贪婪大概是四个里**血量该最低**的那个 —— 它的题是"别让它拖"）。

## 12. 暴食（Gluttony）

> **攻速高**，**每次命中**，会**随机吸取你 血 炁 缠 百分比最高一项的 25%**。

### ⚠️ 这句话有两种读法 —— 需要用户确认（见 §5）

| 读法 | 含义 |
|---|---|
| **(A)** 从血/炁/缠里**挑"你当前百分比最高"的那一项**，吸它 **25%** | "专打你最强的那一项" |
| **(B)** 从血/炁/缠里**随机挑一项**，吸它 **25%** | "不可预测的骚扰" |

⚠️ 原话里"**随机**吸取你 血 炁 缠 **百分比最高一项**的 25%"把两个词放在了一起 ✗
—— 而这两种读法的**玩法完全不同** ✓ (A) 是"惩罚你的强项"，
(B) 是"随机干扰" ✓

### 已有 / 缺什么

| 项 | 状态 |
|---|---|
| ✅ 攻速高 | 轮转 `gapMs` 调小即可 ✓（傲慢是 4000ms）|
| ❌ **"吸取资源"这个效果** | 没有 ✗ —— 现有的 `resource` 只能**扣自己的或目标的绝对值**，没有"**按当前百分比吸**" ✗ |
| ⚠️ **"每次命中"触发** | 需要触发器 ✓ (`onHitTaken` **是活的** ✓ —— 这个有了 ✓) |
