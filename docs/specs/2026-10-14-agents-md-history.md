## 1. §1 类型断言：为什么这两条禁令要这么严

（原文曾写在 `AGENTS.md` §1「为什么」）

`as any` 与 `as unknown as` 会**同时**关掉两件事：

1. **类型检查** —— 编译器不再校验这个值到底是不是 `T`
2. **代码审查的信号** —— 读到 `as unknown as` 时，人无法判断
   这是"我知道自己在做什么"还是"我懒得查类型"

它们最常见的用途是"让报错消失"，而不是"让代码正确"。
一旦出现，后续所有基于类型的重构都会在这几行上失效。

### 与 §3b 的关系（曾经被误用）

`src/core/combat/battleStateTypes.ts` 顶部记过一笔：那条"禁止断言"
不针对**收窄联合类型**的守卫写法。当时有人担心两者冲突，结论是不冲突 ——
§1 禁的是 `as any` / `as unknown as` 这两个**逃生舱**，不是所有的 `as`。
（判据留在源码注释里，因为它是"怎么写这段代码"的知识，不是历史。）

## 2. §2 的由来：两次"重复 → 删"

### 2.1 `hudUtils` 的重复（判据的出生地）

`AGENTS.md` §2 那张"删 / 留 判据"表来自一次真实的清理：同一件事有第二份
表达，而第一份是活的 —— 于是删第二份。`tests/unit/hudUtils.test.ts` 顶部
记着这次核实的经过（按 §2 判据逐项过）。

### 2.2 未实现的机制：为什么"保留类型 + 拒绝静默误用"

引擎里有一批"设计过、还没接线"的能力（`Expr.counter`、
`Hook: 'onPhaseChange'`、`Ability: 'grantSkill'` / `'consume'` …）。
当时的取舍是：

- 类型**保留** —— 删掉会丢设计
- 但**内容不许写** —— 写了会被内容校验器拦下
  （`COUNTER_UNIMPLEMENTED` / `UNSUPPORTED_HOOK` / `ABILITY_UNIMPLEMENTED`），
  `createRegistry` 默认严格，**启动即失败**

这是**有意**的：一份"看起来会生效、实际什么也不做"的内容，比一句 TODO
危险得多（静默无效 / 静默算错是最难查的一类 bug）。判据与对账表在
`src/core/content/capabilityAudit.ts` 顶部。

### 3.2 `src/core/types.ts`：原来以为"不能拆"，判断错了

这里曾写着"类型图是中心辐射的，再切下去会造出类型层的 import 环"
——**那个顾虑被夸大了**：

- `import type` 在编译期**完全擦除**，运行期没有环，不会有"import 是
  undefined"
- 本仓库真踩过的两次环（`data/scale.ts`、`settingsGeometry.ts`）都是
  **值导入**（`const` / 函数），不是类型
- 而且 `events.ts` / `actions.ts` **早就是先例**：它们反向 `import type`
  标识类型，一直没问题

所以后来按**横向切割**（按概念分段各一个文件）拆成了 `src/core/types/`：

| 文件 | 行数（拆的时候） |
|---|---|
| `stats.ts`（属性与修正） | 162 |
| `buffs.ts` | 137 |
| `skills.ts`（技能 + 内容基类） | 133 |
| `effects.ts` | 109 |
| `abilities.ts` | 103 |
| `triggers.ts` | 99 |
| `runtime.ts` | 86 |
| `loadout.ts` / `behavior.ts` | 59 / 50 |
| `resources.ts` | 45 |
| `index.ts`（转发） | 32 |
| `ids.ts` / `encounter.ts` | 22 / 21 |

⚠️ **`index.ts` 转发全部**，所以 `from '../core/types'` 这种整体导入**照旧
可用**（模块解析会走到 `types/index.ts`）。要按需引用时可以改成直接引具体
文件，但那是可选的。

### 3.3 `BattleScene.ts`：教训是"按屏幕区域切"，不是"切到 700 以下"

`render/BattleScene.ts` 曾经是 1421 行。当时的错误是**把"拆到 700 以下"
当成了目标**；但它真正的问题是**一个文件里装了整个战斗页面的所有小区域**
（顶栏 / 血条 / 玩家面板 / 预警条 / 技能栏 / 日志 / 结算…）✗ ——
后来按**屏幕区域**切开，每个区域自己管"造 / 画 / 缩放"。

这就是 §3「700 是信号、不是阈值」那一段的来历。

### 3.4 触线时"压注释/删注释"那几笔账（为什么现在明令禁止）

用户明确指出过（原话）："你为啥要删注释，你应该倾向于拆 util 方法，
或者横向切割。"

当时连续多轮在文件顶到 700 行时选择"压缩注释"甚至"删掉整段注释"，
把文件挤回上限。这是**错的**：

- 本仓库的注释**不是填充物**，它们承担"记录踩过的坑"的职责（哪一版漏了
  什么、为什么不能那样写）。压掉之后**下一个人会重新踩同一个坑**
- 压缩**丢过信息**：`ui/settings/logic.ts` 里"为什么把判定逻辑抽出来"
  （Pixi v8 在 jsdom 里不好跑 → 只能写"能构造、不报错"这种零信息冒烟测试）
  整段被删，而它在别处没有记录
- 删注释是**把成本转嫁给未来**，换取的只是"这一次不用动结构"

`src/ui/settings/logic.ts` 现在顶部还留着"这段理由曾经被我在压注释腾行数
时删掉了"的备注。

### 3.5 为什么是"问"而不是"自动拆"

拆分是有代价的：它会动很多文件的边界、让 `git blame` 断代、
也可能引入循环引用。**在"正在改一个功能"的中间顺手重构整个文件，
是最容易把两件事都做砸的做法。**

所以规则是：**超限必须被指出，但拆不拆由用户决定。**

## 4. §3b 触屏：两次作废的完整叙事

### 4.1 【作废 · 2026-10-12】能力探测（`matchMedia`）不再决定任何事

**原文（保留，用来记住当时为什么那么想）**：

> **能力探测不看 UA**：`render/platform.ts` 用 `matchMedia('(pointer: coarse)')`
> + `(hover: none)`。触屏笔记本的 UA 与普通笔记本一样，UA 判断会漏掉它

**用户明确推翻了它**（原话："**所有 决定 是 键盘还是触屏的 只用唯一 flag**"、
"不用自动判断，由入口显式传"）。

**当时为什么那么想**：UA 会被伪造、且混合设备的 UA 与普通笔记本一样，
"主输入设备是不是手指"看起来只有媒体查询能问。而它当时只决定
"要不要显示键名提示"，所以**故意偏向触屏**（"宁可多认成触屏，代价很小"）。

**实测为什么错**：那个"代价很小"的前提**变了** —— 这个值后来还被拿去决定
「按键」页那**一个**「恢复默认」恢复哪一套键位，于是触屏笔记本上键盘键位
**恢复不了**（用户报的正是"我现在是键盘 为啥显示的 触屏绑定？"）。
一个**故意偏保守**的估计值被升级成**会吞功能**的判断，就是这个 bug 的形状。

**结论（现在的规则在 `AGENTS.md` §3b）**：操作方式是**显式的唯一 flag**。

### 4.2 【作废 · 2026-10-12】触屏按钮的配置入口"就是「按键」页"

**原文（保留，用来记住当时为什么那么想）**：

> 触屏按钮的配置入口**就是**「按键」页 —— 触屏按钮是由键位表
> 机械派生出来的（`touchButtonsFromBindings` = "有键的技能"），
> 所以两者是**同一张表**，不存在"另一套触屏配置"

**用户明确推翻了这条**（原话："触屏和键盘**当然是 2 套**，连
localStorage 都是分 2 个 key 存的，只是**可选技能是一样的**"）。

**当时为什么那么想**：如果触屏另存一套，两套配置会**漂**
（改了键、按钮没跟着变）；"同一张表"结构上不可能漂。

**实测为什么错**：那个派生关系造出一个**死结** ——
技能没绑键 → 触屏上就没有它的按钮；而配按钮的地方是「按键」页，
触屏**按不出键、进不去改键**。于是**纯触屏玩家无法给自己加一个
技能按钮**（而"没绑键的技能"恰恰是最需要加按钮的那一类）。

**中间那版规则（已被下一段取代，但两条结论仍然成立）**：

- 触屏按钮是**用户自己选的一份集合**，存**自己的 key**
  `raid.touchButtons.v1`（与 `raid.bindings.*.v1` 分开）
- 两边**互不派生**
- 派生函数 `touchButtonIdsFromBindings` 只剩两个用途：老存档**迁移一次**、
  以及「恢复默认」的默认值
- 触屏键位就是「按键」页**右下角的一组模拟键位**
  （`ui/settings/TouchSlotPreview`）

### 4.3 【作废 · 2026-10-12 当日第二次改口】独立的「触屏」页

用户原话："**首页点开的设置，可以不要 按键tab**。刚说的触屏的按键设置
方法，最好**集成到 按键tab 里面**。"

所以现在**没有**独立的「触屏」页 —— 触屏键位就是「按键」页右下角的
一组模拟键位，交互是**两步**（规则在 `AGENTS.md` §3b）：

```
① 点一个键位（右下角）→ 它进入"选中"状态
② 点一个技能          → 绑到这个键位（原来那个被顶掉；
                        若这个技能在别的键位 → 两边交换）
点回该键位上已有的那个技能 = 取下（清空这个键位）
```

## 5. §4 e2e 为什么被删掉

**用户原话**："你别跑e2e了，每次都卡住 浪费时间，删掉，逻辑保证ut没问题，
ui截图 验证"

删掉的原因不是"不重要"，而是**成本收益不对**：那两个 CDP 脚本（键盘 /
触屏）**反复卡住**（headless Chrome 残留、rAF 被节流、等待超时），每次
排查都浪费一轮对话；而它们覆盖的东西可以用更便宜的方式覆盖
（逻辑 → 单测；UI → 截图 + 自己看图）。

⚠️ 现状是**硬约束**：`AGENTS.md` §4 写明"不许把截图脚本发展成新的 e2e"。
这条的背景就是上面这段。

### 5.1 "99 个 Chrome 进程"那次泄漏的经过

用户报告过一次实测泄漏：CPU 被跑满 —— 清点时 **99 个 Chrome 进程**，
其中多个 headless 已经跑了**近 3 小时**，GPU 进程各占 4.6~7.8% CPU，
整机 **load average 24**。

**根因**：截图脚本在**收尾阶段会挂住**，而 kill 写在**正常路径的最末尾**
（`child.kill('SIGKILL')`）—— 那一行到不了，Chrome 就一直活着。

**判据**：脚本"挂住"不是"慢"，是"**泄漏**"。所以问题不是"跑得完吗"，
而是"**跑不完的时候谁来收尾**"。（四条防线本身是硬约束，留在
`AGENTS.md` §4。）

### 5.2 rAF 冻结那次排查（CDP 焦点模拟）的完整读数

2026-10-13 实测（Chrome 154.0.8037.98 / `--headless=new`）。症状是
headless 下按一次键，`frameCount` 冻住、战斗 `tick` 停在 0，而且
**再也回不来**（`Page.bringToFront` / `setWebLifecycleState('active')`
都救不回）。

实测对照（每个 case 起一个全新 Chrome，按键后隔 2.2~2.5 秒读读数）：

| 派发形状 | `document.visibilityState` | 独立 rAF 计数（2.2s） |
|---|---|---|
| `rawKeyDown`（无 `text`） | **hidden** | **2**（冻死） |
| `keyDown`（无 `text`） | **hidden** | **3** |
| `rawKeyDown` + `text: ' '`（非空即可） | visible | 134 |
| `keyDown` + `text: 'a'` | visible | 133 |
| `keyUp` / `char` / 鼠标移动 | visible | 151 |
| `keyDown` Tab（无 `text`） | visible | ⚠️ **例外**（原因未查） |

⚠️ 它与"肉鸽路径"**毫无关系**：在**首页**按一个游戏根本不处理的键
（`a`）一样会冻；`?prepare=skip` 直接进战斗也一样会冻（只要按了键）。
那条"肉鸽冻、skip 不冻"的观察是**混淆**：skip 那条路是在按键之前读的
采样点。真正的判据只有一条 —— 按键事件带不带 `text`。

完整推导与实现见 `tools/cdp.mjs` 文件头（那是**代码注释**，属于活的知识，
不搬）。

## 6. 那份"判据表"（§4 测试该留什么）的六个实例

`AGENTS.md` §4 有一张"该留 / 不该留"的判据表。它的来历是 2026-10-13
的两次真实红：

1. `tests/unit/preparePortraits.test.ts` 在**模块顶层**写了一句
   `readFileSync(new URL('../../public/fd2/INDEX.html', import.meta.url))`
   —— 本地有素材，`typecheck` / `test` / `build` 全绿；CI 上 **`import`
   的那一刻就 `ENOENT`**，整个文件红（连"没有素材"这个已知事实都表达
   不出来）。
2. `tests/web/spriteAssets.test.ts` 写了一句
   `import manifest from '../../public/fd2/rgba/manifest.json'` ——
   推到 CI 上 `vite build` 直接挂：
   `TS2307: Cannot find module '.../manifest.json'`。

收口时用户把判据说得比"别读文件"更彻底（原话见 `AGENTS.md` §4），于是
两个文件里的相关断言被**整体删除**（不是 skip、不是 `existsSync` 兜）。

## 7. 章节编号为什么不能随便改

`AGENTS.md` 的小节号被**全仓库按号引用**：`§3` 136 处、`§3b` 83 处、
`§2` 36 处、`§1` 21 处、`§4` 14 处（`src/` / `tests/` / `tools/` /
`docs/`，统计于 2026-10-14）。

所以：

- 清理**只能动叙述**，**不能重排小节号** —— 重排会让这 300 处引用
  静默指错
- 需要新内容时**加子节**（例如 `§4b`），不要插号或让号平移
- 检查办法：`grep -rn "AGENTS.md §" src tests tools docs`
