## 1. 挂在哪（已经查明）

```
index.html          <div id="stage"></div>          ← 画布的家
src/app/bootstrap.ts:60   stage.appendChild(app.canvas)
src/app/loopWiring.ts:177 o.app.ticker.add(() => { … state.frameCount += 1; })
```

⇒ **FPS 的唯一真相就是那个 ticker 回调**（`state.frameCount`，`loopWiring.ts`
每帧 +1；`app/debugProbe.ts` 已经在读它）。**不要**自己再挂一个
`requestAnimationFrame` 去数帧 —— 那会变成第二份"帧"的定义（两份必漂）。

⚠️ **画布是 letterbox 的**（逻辑宽 960，上下留白）—— 用户说的"底部白边"
就是那条带。HTML 层贴在 `#stage` 里、**画布底边之上**即可。

## 2. 这块东西**是 dev 工具，不是游戏 UI**（必须先说清）

AGENTS.md §2 有一条硬规则：**所有 UI 走 canvas（不用 DOM 元素）**。
这个功能**故意破例**，理由要写进模块头：

- 它是**开发/调优工具**（FPS + 录日志），不是玩法界面
- 它**不参与游戏布局**：绝对定位、`pointer-events: none`（只有按钮自己
  `auto`）、不影响 `#stage` 的尺寸计算
- **`?fps=1` 才存在**（不打开时**一行 DOM 都不创建**）

⇒ 模块头写明这三条，并指明"这是 §2 的**有意例外**"，免得后来者以为可以照抄。

## 3. 日志格式（为"AI 读"优化，**不要 dump 每帧**）

一分钟 = 3600 帧，dump 每帧既大又难读。**三层**：

```
# fps-log v1
# url=/raid/?fps=1  canvas=960x540  dpr=2  ua=HeadlessChrome
# commit=<git 短哈希，能从 build 里拿到就填，拿不到写 unknown>
# 时长=63.2s 帧数=3791

t_ms,fps_avg,fps_min,frame_ms_max        ← 每 100ms 一个桶（≈10 行/秒）
0,60.0,58.3,17.2
100,59.8,41.7,24.0
…

# spikes（>2× 中位帧时间 —— "卡顿在哪儿"就看这一段）
t_ms,frame_ms
12400,58.1

# summary
# avg=59.4 p50=16.7 p95=18.1 p99=33.4 min=12.1 max=58.1 掉帧(>33ms)=7 最长卡顿=58.1ms@12400
```

⚠️ 三个数字的定义要写进代码注释，别让它们互相矛盾：
`fps_avg` = 该桶内 `帧数 / 桶时长`；`fps_min` = 该桶内**最长帧**换算的瞬时 FPS；
`frame_ms_max` = 该桶内最长帧的毫秒数。

- 文件名：`fps-log-<YYYYMMDD-HHmmss>.csv`
- 导出：`new Blob([text], {type:'text/csv'})` + `<a download>` + `URL.createObjectURL`
  （用完 `revokeObjectURL`）
- ⚠️ 时间戳**不能用 `Date.now()` 进 `src/core/`**（§2 禁 `Date.now`）—— 但这条
  是 `src/app/` 里的 dev 工具，**可以用**；仍建议只在一处取时间（便于测试时替换）

## 4. 面板与交互

| 元素 | 行为 |
|---|---|
| FPS 数字 | 每秒刷新（别每帧改 DOM 文本 —— 那本身会掉帧）|
| 「录制」| 开始采样：清空缓冲、记录起始时间；按钮变成「停止」|
| 「停止」| 停采样，保留缓冲（可再「导出」）|
| 「导出」| 生成上面那份 csv 并下载 |
| 录制中状态 | 「录制中 · N 样本 · M 秒」|

⚠️ **采样开销要低**：每帧只做"两个数字的加减 + 偶尔 push"；**桶化在采样时完成**
（不是导出时把 3791 个点再过一遍——那是导出卡顿，不是游戏卡顿）。
⚠️ **缓冲上限**要定（例如 30 分钟 / 20 万个桶就停并提示），否则长录会吃内存。

## 5. 验收标准

- [ ] **不带 `?fps=1` 时**：`#stage` 里没有任何新增 DOM（可在单测里断言"工厂返回 undefined"）
- [ ] 带 `?fps=1` 时：底边出现面板，FPS 数字在动
- [ ] 录一段 → 停止 → 导出，得到一个 **csv**，且**结构就是 §3 那三层**
- [ ] **单测**（纯逻辑，不碰 DOM）：
  - 桶化：给定一串帧时间 → 得到正确的桶与 summary（含 p95 / 掉帧数）
  - spikes：只挑 >2× 中位数的那些
  - 阈值边界（比如恰好 2× 中位数算不算 spike —— 定死并钉住）
- [ ] **截图核实**（§4a：用 `?fps=1` 直接进战斗即可，不要走全流程）
- [ ] 四件套全绿：`pnpm run typecheck` → `npx eslint .` → `pnpm run test:run` → `pnpm run build`
- [ ] ⚠️ 别自己 `git push`（AGENTS.md §3c：等用户说"推"）

## 6. 明确**不要**做的事

- ❌ 不要用 `requestAnimationFrame` 自己数帧（唯一真相是 `loopWiring` 的 ticker）
- ❌ 不要把 FPS 面板做成 canvas UI（那样它就"合法"了，但**这个工具的诉求是
  HTML**：好改、好复制、不碰渲染代码）
- ❌ 不要每帧写 DOM 文本
- ❌ 不要把这块东西默认打开（线上不要有调试条）
