# i18n 规范（强制）

> 日期：2026-10-09
> 状态：**强制**。当前只支持中文（`zh-CN`），但从第一天起按多语言架构落地。
> 配套：[数据模型规范](2026-10-09-data-model.md) · [架构与 UI 规范](2026-10-09-architecture.md)

---

## 1. 为什么"以后再加 i18n"不成立

把中文硬编码进代码，之后再抽出来的代价**不是替换字符串**，而是：

1. **内容数据要改结构**（`name: '熵之钟'` → `nameKey: 'entity.entropyClock.name'`），
   所有 `data/` 文件、校验器、测试全部受影响
2. **引擎里会长出"文案逻辑"**（拼字符串、复数、格式化），这些逻辑散落在
   UI 和引擎两侧，事后无法干净剥离
3. **类型安全丢失**：`t('typo.here')` 只能运行时发现

**所以规定：从第一行代码起，任何面向玩家的文字都必须来自 i18n 表。**
唯一允许例外的是 `console.*` 的开发者日志。

---

## 2. 核心原则：引擎持 key，UI 持文案

```
core/  和  data/    只存 key（如 'entity.entropyClock.name'），零文案
        ↓
i18n/               一个 key -> 一个字符串（当前只有 zh-CN）
        ↓
ui/ 和 render/      渲染时查表；数字/百分比走 Intl
```

**理由**：`core/` 必须能在 Node 里跑测试，而测试不该关心文案。
而且以后加载英文时**不需要重新校验内容**（内容里没有任何文案）。

---

## 3. 数据模型变更（强制）

`GameEntity` 及所有内容定义的 `name` / `description` 改为 **key**：

```ts
interface Localized {
  /** 显示名的 i18n key。命名规则见 §5 */
  nameKey: string;
  /** 描述的 i18n key，可选（消耗品/装备需要，技能不需要） */
  descKey?: string;
}

interface GameEntity extends Localized {
  id: EntityId;
  kind: EntityKind;
  icon: string;
  abilities: Ability[];
  // ...
}
```

**受影响并一并改名的字段**（必须一次改完，不许留 `name` 与 `nameKey` 并存）：

| 原字段 | 新字段 | 出现处 |
|---|---|---|
| `name` | `nameKey` | `GameEntity` / `SkillDef` / `BuffDef` |
| `description` | `descKey` | `GameEntity` |
| `StatModifier.source` | `sourceKey` | `StatModifier`（属性溯源面板要显示它！） |

> **`source` → `sourceKey` 是容易漏的一条**：属性溯源面板会显示
> "力量 15 = 基础 10 + 熵之钟 2 + 天赋 3"，这里的"熵之钟"就是玩家可见文案。
> 所以 `sourceKey` 必须是 key。

**仍留在数据里的数字与 id 不受影响**：`id`、`icon`、`value`、`duration`、
`cooldown`、`castTime`、`maxStacks`、`school`、`tags`、`namespace`。
**枚举值用代码常量而非文案**（`school: 'fire'` 而不是 `'火焰'`）。

## 4. 目录与运行时

```
src/i18n/
├─ types.ts          # 从 zh-CN 推导出的 key 类型
├─ locales/
│  └─ zh-CN.ts       # 唯一当前语言；结构上是个嵌套对象
├─ translator.ts     # t(key, params) / number / percent / duration
└─ keys.ts           # 代码里引用的固定 key 常量表
```

```ts
// src/i18n/locales/zh-CN.ts

```

```ts
// src/i18n/translator.ts
export interface Translator {
  /** 按 key 取文案，`{name}` 形式占位符由 params 替换 */
  t(key: string, params?: Record<string, string | number>): string;
  number(value: number): string;                 // 1234 -> '1,234'
  percent(value: number, digits?: number): string; // 0.204 -> '+20.4%'
  duration(ms: number): string;                  // 12500 -> '12.5s'
  plural(key: string, count: number): string;    // 用 Intl.PluralRules
}
```

**性能**：`t()` 是最热路径（每帧可能调用几十次）。所以：

- 启动时把嵌套 catalog **扁平化**成 `Record<string, string>`（一次开销）
- 带参数的模板在首次使用后缓存替换器，避免每帧 `replaceAll`
- **不做运行时 key 校验**（生产环境）；校验在构建期完成（§6）

## 5. Key 命名规则（强制）

```
<domain>.<subject>[.<field>]
```

| 段 | 允许值 | 例 |
|---|---|---|
| `domain` | `common` `hud` `screen` `stat` `resource` `entity` `skill` `buff` `talent` `encounter` `event` `reject` `phase` `setting` | `buff` |
| `subject` | 内容 id 的 camelCase 形式 | `entropySurge` |
| `field` | `name` `desc` `label` `hint` | `name` |

规则：

- **全小写驼峰，不含空格**（`entropyClock` 不是 `entropy-clock`）
- 内容 key 的 `subject` **必须与 `GameEntity.id` 一一对应**
  （`id: 'entropy-clock'` → `entity.entropyClock.name`）。
  这条由校验器强制，避免 key 与内容对不上。
- 禁止在 key 里编码数字/等级（`level2Name` ❌），那属于参数

## 6. 构建期校验（强制）

i18n 的错误必须**在构建/测试期暴露，而不是玩家看到 `entity.foo.name`**。

新增校验码（并入数据模型规范 §11 的校验器）：

| code | 检查 | 级别 |
|---|---|---|
| `MISSING_LOCALE_KEY` | 内容里引用的 `nameKey`/`descKey`/`sourceKey` 在 catalog 里不存在 | **error** |
| `ORPHAN_LOCALE_KEY` | catalog 里有 key，但没有任何内容或代码引用 | warning |
| `KEY_ID_MISMATCH` | `entity.entropyClock.*` 存在但 `id !== 'entropy-clock'` | error |
| `LOCALE_PARITY` | 非基准语言的 key 集合与基准不一致 | **error** |
| `PLACEHOLDER_MISMATCH` | 同一 key 在不同语言里的 `{placeholder}` 集合不同 | **error** |
| `EMPTY_STRING` | 某个 key 的值是空串 | error |

**`LOCALE_PARITY` 是以后加英文时的关键**：漏翻译必须是构建失败，
而不是线上回退到中文。

## 7. 代码层面的强制规则（lint）

| # | 规则 | 实现 |
|---|---|---|
| **I1** | `src/**` 里**禁止出现中日韩字符**（注释除外） | 自定义 ESLint 规则 `no-hardcoded-cjk` |
| **I2** | 只有 `src/i18n/locales/**` 允许出现 CJK | I1 的白名单 |
| **I3** | `core/` 和 `data/` 禁止 import `i18n` | 现有 C1 规则的扩展（引擎不碰文案） |
| **I4** | UI 里禁止字符串拼接生成文案 | 人工评审 + 优先用 `t(key, params)` |

**I1/I2 是最有价值的一条**：它把"忘记走 i18n"从"评审时可能发现"
变成"写下来就报错"。实现方式是在自定义 rule 里扫
`/[\u3040-\u30ff\u3400-\u4dbf\u4e00-\u9fff\uf900-\ufaff]/`。

**例外**：`console.log/console.warn` 里的中文允许（开发者日志），
但要在规则里显式排除 —— 这个例外要写窄，避免被滥用成后门。

## 8. 与事件流的关系

`EventDef` **不带文案**，只带结构。渲染层按 §4 的表查文案：

```ts
// core/events.ts 里的事件（无文案）
{ kind: 'skillRejected', sourceId: 'player', skillId: 'heavy', reason: 'cost' }

// ui 层渲染时
t(`reject.${e.reason}`)                       // '资源不足'
t('skill.heavy.name')                          // '重击'
```

**理由**：同一个事件以后可能要多语言、要被日志系统消费、要能被测试断言。
带文案的事件三者都做不了。

**数字格式化也必须走 `Translator`**，不许用 `toFixed` / 手写模板：
`+20.4%`、`1,234`、`12.5s` 在英文/中文下的规则不同。

## 9. 验收测试

```
I18N-T1  catalog 扁平化后每条 key 都能被 t() 取到，且值非空
I18N-T2  所有 data/ 内容通过校验（无 MISSING_LOCALE_KEY / KEY_ID_MISMATCH）
I18N-T3  同一 key 在 catalog 的基准语言里唯一（扁平化时检测重复）
I18N-T4  带占位符的 key：t('x', {name:'a'}) 正确替换，缺失参数时抛错
I18N-T5  number/percent/duration 的输出与预期字符串一致
I18N-T6  ORPHAN_LOCALE_KEY 检测能找出刻意插入的孤立 key
I18N-T7  lint 规则 I1 实测：在 src/ 里写一行含中文的字符串 → 报错
```

**I18N-T7 必须实测反向用例**（和 M0-8 的 lint 规则一样：不实测等于没写）。

## 10. 为加语言预留的决定

| 决定 | 理由 |
|---|---|
| 基准语言是 `zh-CN`，key 类型从它推导 | 类型安全零成本；加英文时只需保证 key 集合一致 |
| 不做懒加载 / 分包 | 当前只有一种语言，YAGNI。加语言时 `locales/*.ts` 改成动态 `import()` 即可 |
| 不做 RTL 支持 | 中文/英文都不需要；如果以后加阿拉伯语，`ui/layout.ts` 需要加镜像能力 |
| 语言选择存 `localStorage` | 与改键、缩放模式一致；M5 的设置界面里提供 |
| 内容 id 用英文 kebab-case | 与 key 的 `subject` 有确定性映射（§5），可被校验器验证 |
