## 0. 范围与验收

### 0.1 本设计要做的事

| # | 交付 | 验收 |
|---|---|---|
| **A** | **触发器引擎**：`TriggerDef` 真正被执行 | 挂在 buff 上的 `onHitTaken` 触发器能在受伤后产出效果；有内建 CD 防抖 |
| **B** | **眩晕效果**（`EffectKind: 'stun'`） | 玩家被眩晕 3s 内**完全不能行动**；施放中被眩晕会**打断当前施法** |
| **C** | **「欲望印记」反伤被动** | 受伤挂印记（3s）→ 期间再受伤则反伤 18 并**消耗**印记；反伤本身算受击、进日志 |
| **D** | **Boss「色欲」**：2 个伤害技 + 1 个眩晕技 | 能作为备战界面的**第二个对手**被选中并打完一局 |

### 0.2 定位：**机制优先，数值不追求平衡**（用户决定）

用户原话："我觉得可以先不管，这个游戏我准备没有很强的数值性，强调机制，
时机把握和 策略，所以数值简单，而且分得开，先不管细节平衡性，
林晚风和伪名一郎的 平衡性测试也先 skip"

**这改变了"该怎么评价一个 Boss"**，所以必须写清楚：

| 不用的标准 | 换成 |
|---|---|
| 清关时间 / 剩余血线落在同一带宽 | 它逼玩家做的**决定**是否和别的 Boss **不同** |
| 数值强弱排名 | 机制是否可读（前摇 → 应对） |
| N×M 平衡矩阵 | 只要**没有死局**（任何组合都能打通） |

**Boss 之间靠"决定的类型"区分，不靠数值：**

| Boss | 逼你做的决定 |
|---|---|
| 伪名一郎 | "这一下该**打断、闪避、还是格挡**？"（前摇是唯一线索） |
| 色欲 | "**我现在该不该继续打？**"（反伤 + 3 秒锁死惩罚贪刀） |

所以 §2 的数值只承担两个职责：**让战斗能正常进行** + **让机制显形**
（例如反伤必须高到"值得停下来"，低到"不是不能打"）。它**不承担**
"和伪名一样难"这个职责。

⚠️ 记录一下被**主动放弃**的东西：现有 `bossHp.ts` 那套"纯进攻胜但只剩
4 血"的标定方式，本设计**不沿用、也不延拓到色欲**。那段实测记录保留在
原地（它记录了伪名的调参过程），但**不再作为新内容的模板**。

### 0.3 本设计**不包含**

- **玩家眩晕 Boss**（用户明确排除）——
  "暂时不考虑 眩晕boss，即使以后设计出让boss硬直的方法，也不会是直接眩晕"
- **眩晕递减 / 免疫**（用户明确排除）——"没有递减"
- 新 Boss 的美术贴图（先用现有的程序化绘制 / 已有素材回退）
- **平衡数值的标定 / 矩阵 / N×M 验证**（按 §0.2 的定位主动放弃，
  连林晚风 vs 伪名一郎的旧测试也一并 skip）

## 1. 已确认的设计决定（逐条来自用户答复）

| # | 决定 | 出处 |
|---|---|---|
| 1 | 眩晕**只对玩家**施加；玩家不能眩晕 Boss | 用户答复 |
| 2 | 眩晕**3 秒**，期间"无法做任何事情" | 用户："玩家被眩晕后，3s 无法做任何事情" |
| 3 | 眩晕**没有递减** | 用户："没有递减" |
| 4 | 被眩晕时**打断当前施法** | 用户选 A |
| 5 | 反伤模型：印记被**消耗**，玩家能主动规避 | 用户选"推荐" |
| 6 | 反伤形式：**纯反伤**（直接扣血），不打断、不是真实反击 | 用户选"推荐" |
| 7 | **印记在生效期间不被刷新** | 用户："关于印记 你说的没问题" |
| 8 | **反伤算受击，进日志** | 用户："反伤算 受击，进日志" |
| 9 | 技能构成：2 个伤害技（快/慢各一）+ 眩晕技 + 反伤被动 | 用户选"推荐" |

### ⚠️ 决定 7 为什么是**平衡的命门**

如果"受伤就挂印记"每次都刷新持续时间，那么玩家只要持续攻击，印记就
**永不消失** → 每一下都被反伤，规避窗口变成 0。

那样反伤就从"博弈"退化成"每次攻击固定扣 18 血"，玩家唯一的选择是不打 ——
而"不打"在本作里等于输（有时限，Boss 血量固定）。

**规则**：`onHitTaken` 挂印记时若**已有印记则不再挂**（不刷新持续时间）。
这样每次反伤之后，玩家都拿到一个明确的 **3 秒安全窗口**。

## 2. 「色欲」技能表

⚠️ **本作不分伤害类型**（用户决定："先不要伤害类型，所有伤害都是同一个类型，
不分物理 火焰 奥术 之类的"）。

所以技能表里**只有伤害数值**，不存在"物理/火焰/奥术"的区分与克制关系。
`色欲` 与 `伪名一郎` 的区别完全来自**机制**，不来自元素。

| 技能 | 类型 | 前摇 | 效果 | 冷却 |
|---|---|---|---|---|
| 「轻吟」 | 快招 | 0.9s | 12 伤害 | **2s** |
| 「缠绕」 | 慢招 | 2.0s | 30 伤害 | 9s |
| 「魅惑」 | **眩晕** | 1.4s | 玩家**锁死 3s** + 打断其当前施法 | **6s** |
| 「欲望印记」 | **被动**（buff 上的触发器） | — | 受伤 → 挂印记 3s → 期间再受伤则反伤 **18** 并消耗印记 | 触发内 CD 1s |

### 2.1 三个规避渠道（可读性的关键）

本作的**可读性规律**是"前摇是唯一线索"。三个技能各自留了一条路：

| 技能 | 能打断？ | 能闪避？ | 能格挡？ |
|---|---|---|---|
| 「轻吟」 | ✅ | ✅ | ✅ |
| 「缠绕」 | ✅ | ✅ | ✅ |
| 「魅惑」 | ✅ | ✅ | **❌**（格挡挡不住精神攻击） |

⚠️ **「魅惑」只能靠打断或闪避**，格挡无效 —— 这是它和另外两个技能的
区别所在，也是"看到 1.4s 前摇必须做决定"的来源。格挡无效这件事
**必须在 UI 上说清楚**（技能描述 + 图标），否则玩家会以为格挡坏了。

### 2.2 战斗节奏意图

`色欲` 的伤害低于 `伪名一郎`（30 vs 36 的高伤），它**不靠伤害压制**，
而是靠"你不敢连打"：

- 连打 → 被反伤 → 血量被自己打下去
- 停手 → 时限压力上来（Boss 血量固定，玩家 DPS 掉）
- 刚好在连打中被「魅惑」→ **3 秒白挨**

所以这个 Boss 惩罚的是**贪刀**，而不是考反应。

## 3. 触发器引擎（反伤被动的地基）

### 3.1 现状

`TriggerDef` 有**完整的类型定义与数据校验**，但**引擎里没有任何地方执行它**：

- `onHitTaken` 等 hook 只在 `types/triggers.ts` 里声明，无派发点
- 仓库里**没有任何内容用过触发器**

所以「欲望印记」不能只靠写数据实现，**必须先把这个执行器建起来**。

### 3.2 方案：结算完成后统一派发

```
战斗结算（一次施放 / 一次命中处理完）
      ↓
引擎在既定的 hook 点派发事件
      ↓
按 owner 收集带 triggers 的 buff → 逐个判 when / cooldownMs / chance
      ↓
产出 Ability[] → **复用现有的 ability 执行器**
```

⚠️ **关键取舍：hook 只在"结算已完成"的点派发，不在结算中途插入。**

中途派发的后果是"反伤 → 又触发反伤 → 再触发…"这类嵌套链**在整个战斗里
到处都可能发生**，很难保证不死循环。而"结算完再派发"天然只有一层，
嵌套深度有上界。

### 3.3 反伤自身算不算受击

| 问题 | 决定 | 理由 |
|---|---|---|
| 反伤算一次受击吗？ | **算** | 用户确认；它会写日志、会飘字，玩家能复盘 |
| 那会不会无限弹？ | 不会 | ① 反伤是 `色欲` 的 buff 触发，玩家侧没有同款；② 触发器有 `cooldownMs`（反伤 1s）防抖 |
| 闪避掉了算受伤吗？ | **不算** | `onHitTaken` 只在**真正造成伤害后**触发。否则"闪避"反而白送 Boss 一个印记 —— 与直觉相反 |

### 3.4 本期只做必要的 hook

**只派发 3 个**：`onHitTaken`（反伤被动用）、`onBuffApplied` / `onBuffExpired`
（印记的挂上与到期，日志与 UI 都要）。

其余 hook（`onCritTaken` / `onAvoided` / `onKill` …）**本期不派发** ——
它们的类型还在，但引擎不认。这样做的理由：一次把所有 hook 都接上会
把一个"给反伤用"的小机制变成横跨整个结算管线的大改动。

⚠️ 代价要写清楚：**没派发的 hook 是"静默无效"的** —— 内容作者写了一个
`onKill` 触发器，它不会报错也不会生效。所以要在 `validate.ts` 里加一条
**明确的不支持警告**，而不是让它悄悄失效。

## 4. 眩晕效果

### 4.1 语义

`EffectKind` 增加 `'stun'`。它等价于"给目标挂一个**禁行动 buff**"：

| 规则 | 决定 |
|---|---|
| 禁用范围 | **完全不能行动** —— 不能出招、不能闪避、不能移动方向（用户确认） |
| 打断当前施法 | **会打断**，且**不退冷却**（用户选 A） |
| 递减 | **无** |
| 谁能被眩晕 | **只有玩家**（`色欲` 的技能对它自己无效） |

⚠️ **"不退冷却"是有意的**：玩家在「缠绕」读条快完成时被魅惑，那个技能的
冷却照走。这是"贪刀"代价的一部分；退冷却会让眩晕变成"免费重置"，反而
削弱了这一击的分量。

### 4.2 实现要点

- **复用现有的"技能被拒绝"通道**给玩家反馈（UI 显示"眩晕中"），
  而不是新造一个输入状态 —— 输入层已经在处理"技能不可用"的显示
- 禁用检查放在**输入层接受 Action 之前**（一处），而不是在每个技能里判
- 眩晕 buff 的持续时间就是禁用时长，**不要**另存一个计时器
  （两处真相必然出现"buff 没了但还动不了"）

触发器**在 core 内**产出 `Ability[]`，不反向调用渲染层。

## 6. 验收与测试

### 6.1 单元测试（主力）

| 测什么 | 关键用例 |
|---|---|
| 触发器执行 | 受伤后触发；`when` 不满足不触发；`cooldownMs` 内不重复；`chance` 走种子化 RNG |
| **印记不刷新**（§1 决定 7） | 印记已存在时再受伤，**剩余时间不变**（这是平衡命门，必须有断言） |
| 反伤 | 消耗印记；反伤算受击、进日志 |
| 闪避不算受伤 | 被闪避的攻击**不挂印记** |
| 眩晕 | 期间拒绝 Action；打断施法且**冷却不退**；到期后恢复 |
| 内容校验 | 未派发的 hook 给**明确警告**（不静默失效） |

### 6.2 平衡实测（**本次不做**，见 §0.2）

按 §0.2 的定位，本次**不做**清关时间 / 血线的标定，也不改
`data/entities/bossHp.ts`（那是伪名的实测记录，保留原样）。

**怎么做才算"数值分得开"** —— 这个判据比"调平"弱得多，也便宜得多：

1. 色欲的血量**不用**反推。先给一版明显能打完的量级，玩一遍
2. 确认**不存在死局**：不闪不挡、纯进攻循环也能打死（否则机制就变成了
   "必须完美规避"，与"数值简单"的定位冲突）
3. 确认**机制显形**：
   - 反伤要**看得出**（飘字 + 日志，见 §1 决定 8）
   - 「魅惑」的 3 秒锁死要**明显**（§4.2 的 UI 反馈）
   - 玩家尝试"连打"时要能感到"这样打不划算"—— 但**不是**"完全不能打"

⚠️ **不做**但不删除判据：将来真要平衡时，§0.2 的"决定是否不同"仍是
第一标准，而不是数值带宽。

### 6.3 端到端

用现成的入口跑一局「色欲」：

```
http://localhost:5273/?prepare=skip
```

⚠️ 该入口目前**写死默认对手**（`selection.bossId` 的默认值）。要测第二个
Boss，需要让它接受 `?boss=lust`。这是本设计的一个**小前置改动**。

## 7. 风险

| 风险 | 应对 |
|---|---|
| 反伤数值没调好 → 机制从"博弈"变成"不能打" | 18 是先给的可玩值；反伤**不吃增伤**（`ignoreModifiers`），避免玩家增伤时把自己秒了。判据见 §6.2 第 3 条 |
| 数值追求"和伪名一样难" → 跑偏 | 按 §0.2，Boss 之间靠**决定的类型**区分，不靠数值排名 |
| 触发器引擎把结算管线搅乱 | hook 只在结算完成后派发（§3.2）；先只接 3 个 hook |
| 「魅惑」格挡无效被当成 bug | 技能描述里写明"格挡无效"，且图标上区分 |
| 3s 完全锁死在触屏上"看着像卡死" | 眩晕期间 UI 必须**明确显示**状态（复用技能拒绝通道），不能只是没反应 |
| `main.ts` / `content.ts` 触到 700 行 | 按 AGENTS.md §3 **拆 util**，不删注释 |
