# 斗

一个**单挑 Boss**的实时战斗数值模拟器。第三人称视角、无位移、全键盘操作、
PixiJS 像素渲染。

> **项目状态：M0–M6 完成，MVP 可玩。** 367 个测试（含黄金重放
> + 可扩展性验收）+ CDP 端到端验证。
>
> 2026-10-09 做过一次**数值与交互重做**：单一刻度（100 血 / 10 伤害）、
> 0.1 秒逻辑步长、一格一字的技能组、按住式格挡、弧形冷却遮罩。
> 项目显示名已改为「斗」（仓库名与发布地址 `…/raid/` 保持不变）。
>
> **可以在浏览器里真的打完一场 Verrot 的 Boss 战**：全键盘操作、
> 前摇预警、闪避/格挡、Boss 阶段转换与狂暴、战斗结算。
> 实测一局约 108 秒、总伤害 17 万、DPS 约 1580。
>
> 剩余工作集中在表现层打磨（正式像素图标与动画、音效、设置持久化）
> 与内容扩充。

## 这是什么

- **一场战斗 = 一个 Boss。** 每场有**时限**（超时判负）和**狂暴机制**
  （超时后 Boss 伤害翻倍），Boss 有带前摇的技能、阶段转换、可打断的读条。
- **没有位移，但需要"躲"。** Boss 技能在 **hit frame** 一次性判定，
  你按下的闪避/格挡会给自己挂一个 **300ms 的短时无敌/减伤 buff**——
  时机对了就免伤，错了就吃满。**判定窗口就是 buff**，不是另一套系统。
- **技能派生。** 施放技能 A 后开启一个 1.5s 的"派生窗口"，
  技能 B 只有在这个窗口内可用。同样是 buff 存在性判断。
- **玩家和 Boss 数值对等。** 两边跑**同一个引擎、同一套数据模型**，
  区别只有输入来源：玩家是键盘，Boss 是数据驱动的行为数组。
- **全键盘。** 没有 WASD，主键区全部留给技能（`1-6` `Q E R T F G Z X C V`）。

## 架构核心：一条硬边界

```
        ┌──────────────────────────────────────────────┐
        │  core/   纯确定性模拟引擎                       │
        │  (state, input, dt) -> (state', events)      │
        │  零依赖 · 无 DOM · 无 Math.random · 可在 Node 跑 │
        └──────────────────────────────────────────────┘
                 ▲                          │
      Action[]   │                          │  Snapshot + Events
                 │                          ▼
        ┌────────────────┐        ┌──────────────────────┐
        │ input/ 键盘     │        │ render/ Pixi 消费者   │
        └────────────────┘        └──────────────────────┘
```

旧版本（已删除，可从 git 历史取回，见文末）失败的原因是**引擎逻辑写在了 React 组件的 `useCallback` 里**，
伤害结算、buff 计时、公式全靠 `useEffect` 监听时间变化来驱动。
新版本用五条**由 lint 强制**的约束把它彻底隔开（见架构规范 §2.1）：

1. `core/` 不许 import `pixi` / DOM / UI
2. `core/` 里不许出现 `Math.random` / `Date.now`
3. `render/` 不许反向依赖 `core/` 内部
4. `core/` 里不许出现异步
5. 状态必须可结构化克隆、可哈希

**验收标准**：`core/` 能在 Node 里跑完一整场战斗并断言结果——不启动浏览器。
只有这个测试通过，才允许开始写 UI。

### 黄金重放

`tests/golden/replay.test.ts` 把**一整场战斗**压缩成一个可提交、可 diff 的常量：

```
固定种子 + 固定玩家策略  →  胜负 / 击杀用时 / 随机数终态 / 双方终局状态
```

它防的是**静默的行为变化** —— 改了一个数值、门禁顺序、AI 优先级或 tick 语义，
重放会立刻暴露。因为引擎没有 `Math.random`（lint 硬约束 C2）、
随机数状态存在 `BattleState` 里，重放是逐位确定的。

**这组测试已经抓到过真问题**：暴击判定根本没实现（`crit: false` 是硬编码的），
而 `BattleState.rngSeed` 从未更新（永远等于初始种子），
也就是"随机数状态在状态里、所以可重放"这条约定**实际上是假的**。

### 操作

本作**没有位移**，所以左手最自然的那块键区整体留给技能。
6 个技能铺在一块 **2×4** 上，每个技能一个字，图标就用那个字（楷体）：

```
上排   Q  W  E  R
下排   A  S  D  F
       ↑ 技能        ↑ 空着（留给以后的新技能）
```

| 键 | 字 | 消耗 | 效果 |
|---|---|---|---|
| `Q` | **攻** | 10 炁 | 普攻，造成 10 点伤害 |
| `W` | **轰** | 50 缠 | 造成 30 点伤害并使目标易伤 |
| `E` | **凝** | 50 缠 | 自身增伤 20%，持续 30 秒 |
| `R` | **破** | —（5 秒 CD） | **打断目标的任何招式** |
| `A` | **闪** | 30 炁（1 秒 CD） | 0.5 秒完全无敌。**会打断自己的读条** |
| `S` | **防** | 按住，每 0.1 秒 2 炁 | 持续减伤 55%。只由按住状态与炁决定 |
| `Esc` | | | **打开设置**（顺带暂停） |
| `,` | | | 打开设置的备用快捷键 |
| `↑` + `Enter` | | | 也可选中右下角的齿轮打开设置 |
| `Enter` | | | 战斗结束后重开 |

### 数值刻度

玩家状态条上有三个单字：**血 / 炁 / 缠**。双方血量都是 **100**，
炁与缠的上限也是 **100**。所有数值都是可读的小整数。

- **逻辑步长 0.1 秒** —— 引擎内部仍是 60Hz（渲染要 60fps），
  但游戏逻辑以 0.1 秒为最小单位，所以内容里不会出现 0.267 秒这种脏数字。
- **公共冷却 0.5 秒**
- **炁**（短循环资源，代码里的 `energy`）：每 0.1 秒自动恢复 1 点。
  供普攻与防御技（闪 / 防）消耗 —— 所以"该躲时躲不躲得起"由它决定。
- **缠**（积攒型资源，代码里的 `douqi`）：**按伤害换算** ——
  造成 1 点伤害得 1 点，受到 1 点伤害也得 1 点。
  供「轰」「凝」这类高威力招式消耗。

> 标识符与中文名不是直译关系：`energy` 是**炁**、`douqi` 是**缠**。
> 这两个中文名在 2026-10-09 对调过一次，标识符出于历史原因保留了。
> **改中文名只动 `src/i18n/locales/`**，不影响引擎。

### Boss 的三个招式对应玩家的三张牌

| Boss 招式 | 前摇 | 伤害 | 该用什么 |
|---|---|---|---|
| 重斩 | 0.8 秒 | 18 | 硬吃或用「防」 |
| 横扫 | 1.2 秒 | 30 | **「闪」**（前摇够长，来得及反应） |
| 蓄能 | 1 秒 | — | **「破」**（打断它等于免掉 10 秒的 30% 增伤） |

Boss 的所有招式都**可以被打断 / 闪避 / 格挡**。

## 开发



```bash
pnpm install
pnpm run dev            # 本地开发（http://localhost:5273）
pnpm run typecheck      # tsc --noEmit
pnpm run lint           # 含架构硬约束 C1-C5 / I1-I3
pnpm run test:run       # 87 个单测（含 lint 反向用例）
pnpm run test:core      # 只跑纯逻辑，node 环境，不碰浏览器
pnpm run verify:e2e     # CDP 端到端：验证 tick 真的在 60Hz 推进
pnpm run build          # 产出 dist/（base 为 /raid/）
```

**lint 的硬约束不是风格偏好**：`core/` 里出现 `Math.random`、`import 'pixi.js'`、
`document`、`await`、`new Map()`，或者 `src/` 下写死中文，都会**构建失败**。
反向用例在 `tools/lint-fixtures/`，由 `tests/unit/lintRules.test.ts` 断言规则真的生效
（不实测的 lint 规则等于没写）。

推送 `main` 会触发 [.github/workflows/deploy.yml](.github/workflows/deploy.yml)：
typecheck → lint → test → build → 发布到 GitHub Pages。
**测试或 lint 不通过则不会发布。**

### 线上地址（保持不变）

**https://hdnray.github.io/raid/** —— 路径是 `/raid/`，不是仓库同名的
`/raid-simulator/`。新项目的 Vite `base` 必须是 `/raid/`，
路由必须是 **hash 形式**（`#/battle`），页面标题保持 `斗`。

新项目就绪前（`src/main.ts` 不存在），`deploy.yml` 只做校验、**不发布**，
所以线上会保留 2022 年的旧版本，不会被空产物覆盖。

### 分辨率

逻辑分辨率固定 **960×540**（16:9）。canvas 内部尺寸在生命周期内**永不改变**，
缩放完全交给 CSS，多余区域用黑边填充。默认 `fit` 模式（按
`min(w/960, h/540)` 等比填满），设置里可切 `integer`（整数倍 + 绝对锐利）。
细节见架构规范 §10。
